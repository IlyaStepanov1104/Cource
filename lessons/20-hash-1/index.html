База контактов - 1 000 000 записей

contacts = [
    ("Alice",   "+7 900 111-22-33"),
    ("Bob",     "+7 900 444-55-66"),
    # ... ещё 999 998 записей
]

Нужно найти телефон по имени. Как?

Поиск в списке

def find(contacts, name):
    for n, phone in contacts:
        if n == name:
            return phone
    return None
В худшем случае - 1 000 000 итераций. Сложность: O(n)

А если dict?

contacts = {
    "Alice": "+7 900 111-22-33",
    "Bob":   "+7 900 444-55-66",
}

phone = contacts["Alice"]  # мгновенно!

Сложность: O(1) - независимо от размера

Простая хеш-функция

def _hash(key, size):
    return sum(ord(c) for c in key) % size

Пример для "cat", size = 10:

Требования к хеш-функции

  • Детерминированность - один ключ всегда даёт один индекс
  • Скорость - вычисление за O(1)
  • Равномерность - ключи распределяются по ячейкам без скоплений
Плохая хеш-функция = всё в одну ячейку = O(n) вместо O(1)

hash() в Python

hash("apple")    # например: 1740259866648
hash(42)         # 42
hash((1, 2, 3))  # хеш кортежа
hash([1, 2, 3])  # TypeError!
  • Работает для неизменяемых типов: str, int, tuple
  • Список нельзя - он изменяемый, хеш стал бы нестабильным
  • Python 3.3+ - результат разный при каждом запуске (защита от атак)

Коллизии

Коллизия

Два разных ключа дают одинаковый индекс

Коллизии неизбежны - ключей бесконечно много, ячеек конечное число

Задача - не избежать коллизий, а грамотно их обработать

Пример коллизии

"abc"

97 + 98 + 99 = 294

294 % 10 = 4

"bca"

98 + 99 + 97 = 294

294 % 10 = 4

Оба ключа попадают в ячейку [4] - коллизия!

Метод цепочек (Chaining)

В каждой ячейке хранится список пар (key, value)

buckets = [
    [],                            # [0]
    [],                            # [1]
    [("cat", 42)],                 # [2]
    [],                            # [3]
    [("abc", "x"), ("bca", "y")],  # [4] - коллизия!
]

При поиске: индекс -> пройти по цепочке -> сравнить ключи

Load factor

Коэффициент загрузки = n_items / n_slots

# 7 элементов в массиве из 10 ячеек
load_factor = 7 / 10  # = 0.7
  • Если load_factor > 0.7 - много коллизий, деградация до O(n)
  • Решение: массив побольше и перехэшировать все элементы

Что запомнить

  • Хеш-функция превращает ключ в индекс массива - поэтому O(1)
  • Коллизии неизбежны - решаются методом цепочек (chaining)
  • Load factor > 0.7 - таблица расширяется автоматически
  • dict в Python - это оптимизированная хеш-таблица
