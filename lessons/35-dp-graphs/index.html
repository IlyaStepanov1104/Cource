Где ошиблась Дейкстра

  • Дейкстра закрыла A с расстоянием 2
  • потом дошла до B: ребро B -> A с весом -4 даёт 1
  • но A уже закрыта, и C, T посчитаны от старого значения
  • над вершинами: ответ Дейкстры / правильный ответ

Отрицательный цикл

  • добавили ребро C -> B: цикл A - C - B - A
  • его вес: 1 + 1 - 4 = -2
  • после V - 1 = 4 раундов делаем ещё один, и расстояния снова уменьшаются
Значит, есть отрицательный цикл: кратчайшего пути до A, B, C, T не существует

Динамическое программирование

Три вопроса динамики

1
Что храним? Состояние: "число путей из S до вершины v"
2
Как считаем? Переход: сумма ответов по стрелкам, входящим в v
3
В каком порядке? Так, чтобы всё нужное было уже посчитано
Ответили на три вопроса - алгоритм готов

Порядок = топологический

  • тот же граф, вершины выстроены в топологическом порядке (занятие 20)
  • все стрелки идут слева направо
  • идём слева направо: к каждой вершине все, кто ведёт в неё, уже готовы

А если есть цикл?

  • чтобы посчитать A, нужен ответ для C
  • для C нужен B, а для B - сам A
  • вершина ждёт сама себя: подходящего порядка нет
Динамика по вершинам работает на графе без циклов (DAG)

Bellman-Ford - тоже динамика

1
Состояние: самый дешёвый путь до v, в котором не больше k рёбер
2
Переход: путь из k рёбер = путь из k - 1 ребра + ещё одно ребро
3
Порядок: k = 1, 2, 3, ... - это и есть раунды
Цикл в графе есть, но k только растёт - по кругу таблица не пойдёт

Самый длинный путь

кратчайший и длиннейший путь в графе без циклов

Сколько дней на проект?

  • команда делает игру
  • стрелка - работа, число - сколько дней она идёт
  • вершина - момент "всё, что в неё входит, готово", дальше можно начинать следующие работы
  • людей много: независимые работы идут одновременно
Через сколько дней наступит T - игра готова?

Это самый длинный путь

  • T наступит, когда закончится самая долгая цепочка работ
  • значит, ответ - длиннейший путь из S в T
  • подойдёт ли Дейкстра, если заменить min на max?
  • нет: Дейкстра закрывает вершину навсегда, а более длинный путь до неё может найтись позже

С циклами трудно, без них легко

Граф с циклами

путь может ходить по кругу, а если запретить повторять вершины, задача становится очень трудной: быстрого алгоритма не знает никто

Граф без циклов

повторить вершину невозможно в принципе: хватает одного прохода в топологическом порядке

Состояние и переход

1
best[v] - самый долгий путь из S до v; best[S] = 0
2
best[v] = max из best[u] + вес по всем стрелкам u -> v
3
на картинке: max(3 + 4, 2 + 1) = 7

Шаг 1: топологический порядок

  • порядок: S, A, B, C, D, T
  • все стрелки идут слева направо
A и B можно поменять местами - ответ не изменится

Шаг 2: заполняем best

вершинаоткудаbest
Sстарт0
AS + 33
BS + 22
Cmax(A + 4, B + 1) = max(7, 3)7
Dmax(A + 2, B + 5) = max(5, 7)7
Tmax(C + 3, D + 2) = max(10, 9)10

Ответ: 10 дней

  • самая долгая цепочка: S - A - C - T
  • её называют критический путь: задержится любая работа на нём - сдвинется вся игра
  • работу B -> D можно задержать на день, и ничего не изменится

Откуда пришли

  • вместе с best[v] запоминаем parent[v] - из какой вершины пришёл максимум
  • пунктир: parent для каждой вершины
  • идём от конца назад: T <- C <- A <- S
  • разворачиваем - получаем путь

Кратчайший путь тоже можно

  • меняем max на min
  • ребро B -> C теперь -3: C = min(3 + 4, 2 - 3) = -1
  • отрицательные веса не мешают: вершину считаем один раз, когда всё входящее уже готово

Что быстрее

алгоритмгде работаетвремя
BFSрёбра без весовO(V + E)
Дейкстравеса >= 0O(E log V)
Bellman-Fordлюбые весаO(V * E)
динамика по топ. порядкутолько без циклов; любые веса; и min, и maxO(V + E)
Граф без циклов - самый удобный случай: быстро и без ограничений на веса

Клетчатое поле

тот же граф, только нарисованный сеткой

Поле - это граф

  • черепашка стоит в левом верхнем углу
  • нужно в правый нижний, ходить можно только вправо и вниз
  • клетка - вершина, ход - стрелка

Почему нет циклов

  • в клетке: номер строки + номер столбца
  • любой ход увеличивает это число на 1
  • вернуться туда, где уже был, нельзя
Значит, поле - это DAG, и динамика работает

В каком порядке

  • к клетке её верхний и левый соседи уже готовы

Состояние больше, чем вершина

когда в графе есть циклы, а динамика всё равно нужна

Маршруты ровно из 3 рёбер

  • сколько маршрутов из A в D ровно из 3 рёбер?
  • вершины повторять можно
  • в графе есть цикл B - C - B: обычная динамика по вершинам не работает

Состояние = (вершина, шаги)

  • на каждый шаг k - своя копия вершин
  • ребро u -> v превращается в (u, k) -> (v, k + 1)

В графе состояний циклов нет

  • каждая стрелка ведёт из слоя k в слой k + 1
  • вернуться в прошлый слой нельзя
  • значит, это DAG, и порядок известен: слой за слоем
Цикл был в исходном графе, а в графе состояний его нет

Считаем слой за слоем

kABCD
01000
10110
20112
30112
Ответ: 2 маршрута, A - B - C - D и A - C - B - D

  • в 787. Cheapest Flights Within K Stops состояние было (город, пересадки)
  • слой - число перелётов, переход - ещё один перелёт
  • в каждой клетке храним минимальную цену, а не число путей

Обязательно через C

  • состояние: (вершина, были ли уже в C) - две копии графа
  • стрелка в C переводит из верхней копии в нижнюю
  • ответ - путей до T в нижней копии: 2
