Разбор ДЗ

1319. Number of Operations to Make Network Connected

Условие

n компьютеров, часть уже соединена кабелями. За одну операцию можно взять любой кабель и переставить между двумя другими компьютерами.

Найти минимум операций, чтобы связать все компьютеры в одну сеть, или вернуть -1, если кабелей физически не хватает.

Идея решения

1
Чтобы связать n компьютеров, нужно минимум n - 1 кабель
2
Кабелей меньше, чем n - 1 - соединить в принципе невозможно, ответ -1
3
Иначе считаем число компонент связности через DFS - "лишние" кабели внутри компонент можно переставить

Разбор на примере

n = 4, connections = [[0,1], [0,2], [1,2]]
✓
Кабелей 3, нужно минимум n - 1 = 3 - хватает
✓
DFS: компонента {0,1,2} и компонента {3} - всего 2 компоненты
=
Ответ = components - 1 = 1 операция
5

Критичное ребро

что если его убрать?

Возвращаемся к домашке

Мы брали "лишний" кабель внутри одной компоненты связности (КС) и переставляли его в другую - чтобы объединить их.

✓
Ребро 2-3 - часть цикла. Уберём его - компонента всё равно целая, через 3-0-1-2. Кабель можно переносить
!
Ребро 4-5 - цикла рядом нет. Уберём его - компонента разваливается на {0,1,2,3,4} и {5,6} - вместо одной КС получили две!

Не все рёбра одинаковы

Иногда удаление ребра ничего не меняет - до всех вершин всё ещё можно добраться.

А иногда удаление ребра разрывает граф на несколько кусков.

Как найти именно такие - критичные - рёбра, не перебирая их все по одному?

Примеры из жизни

Мост через реку

единственная переправа между районами

Кабель между ЦОДами

единственная связь между дата-центрами

Сломается это ребро - часть сети полностью отрезана от другой

Определение: мост

Мост - ребро, чьё удаление увеличивает число компонент связности

Уберём ребро 1-3 - граф распадётся на два треугольника. Любое другое ребро убрать - граф останется связным.

Наивный подход

1
Берём ребро, временно удаляем его из графа
2
Запускаем DFS, считаем число компонент связности
3
Стало компонент больше - это мост. Возвращаем ребро обратно
4
Повторяем для каждого ребра графа
На каждое из E рёбер - отдельный DFS за O(V+E). Итого O(E * (V+E))

Слишком медленно

Для графа с 10^5 рёбер это ~10^10 операций - точно не уложимся в разумное время.

Хотим находить все мосты сразу, за один проход DFS - O(V + E)

Алгоритм Тарьяна

поиск мостов за один DFS

Что такое дерево

Дерево - связный граф без циклов: направленный, от корня к любой другой вершине идёт ровно один путь.

Стрелки идут вниз от корня к потомкам. Ни один путь никогда не возвращается наверх - циклов нет.

DFS строит именно такое дерево из обычного графа - беря лишь подмножество его рёбер: те, по которым реально прошла рекурсия

DFS-дерево и обратные рёбра

Запустим DFS из вершины 0. Часть рёбер станут рёбрами дерева (по ним идёт обход), остальные - обратными рёбрами (back edges).

━━ рёбра дерева    ┅┅ обратные рёбра (back edges)

tin[v] - время входа

Представь: DFS идёт по вершинам и подписывает номерок на каждой - в каком порядке первый раз в неё зашли. Как номерок в очереди.

Просто счётчик времени, который увеличивается на 1 при каждом заходе в новую вершину

low[v] - можно ли обойти ребро наверх

Стоим в вершине v. Вопрос: если убрать ребро, по которому мы сюда пришли - останется ли путь наверх, в обход, через какое-то другое ребро?

low[v] - это самый маленький tin, до которого можно дотянуться из v (или из того, куда мы попали дальше рекурсией), сделав ровно один "прыжок назад" по обратному ребру.

У вершины 2 есть обратное ребро прямо в вершину 0 (tin=0). Значит low[2] = 0 - в обход можно дотянуться очень высоко наверх

Как считается low[v]

Сосед ещё не посещён

заходим туда рекурсией, потом тянемся

low[v] = min(low[v], low[to])

Сосед уже посещён

не заходим, сразу тянемся к нему - кроме вершины, откуда мы сами пришли

low[v] = min(low[v], tin[to])

В начале low[v] = tin[v], дальше только уменьшаем

Условие моста

Ребро (v, to) - мост, если low[to] > tin[v]

Смысл: из to (и всего, что под ним) не существует обратного ребра, ведущего в v или выше - без ребра (v, to) туда вообще не добраться.

Трассировка: спускаемся

0
tin[0]=low[0]=0. Идём в 1
1
tin[1]=low[1]=1. Идём в 2
2
tin[2]=low[2]=2. Сосед 0 уже посещён и это не родитель - back edge
!
low[2] = min(2, tin[0]=0) = 0. Возврат в 1: low[1] = min(1, 0) = 0
?
Мост 1-2? low[2]=0 > tin[1]=1? Нет - не мост

Трассировка: второй треугольник

3
Из 1 идём в 3: tin[3]=low[3]=3
4,5
3 → 4 → 5, затем back edge 5-3: low[5]=3, low[4]=3, low[3]=3
↑
Возврат в 1: low[1] = min(low[1]=0, low[3]=3) = 0
!
Мост 1-3? low[3]=3 > tin[1]=1? Да! Ребро (1,3) - мост

Ловушка: кратные рёбра

Если между v и parent есть два разных ребра, нельзя просто пропускать соседа "равного parent".

Иначе второе ребро к parent посчитается как back edge, и настоящий мост рядом с ним будет пропущен по ошибке.

Решение: передавать в DFS не вершину-родителя, а индекс ребра, по которому пришли, и пропускать именно его

Точки сочленения

articulation points

Определение

Точка сочленения - вершина, чьё удаление увеличивает число компонент связности

В нашем графе - вершины 1 и 3: убери любую из них, треугольники разъединятся.

А если моста нет?

Возьмём два треугольника, склеенных не ребром, а прямо по вершине.

Убери любое ребро - граф всё равно останется целым (у него есть цикл). Мостов тут нет вообще
Убери вершину 2 - треугольники сразу распадаются на {0,1} и {3,4}
Вершина 2 - точка сочленения, хотя рядом с ней нет ни одного моста. Это два разных понятия - они просто совпали в прошлом примере

Чем отличается от моста

Мост

критичное ребро

условие: low[to] > tin[v]

Точка сочленения

критичная вершина

условие: low[to] >= tin[v]

Считаются в одном и том же DFS, по тем же массивам tin/low

Условие

Вершина v (не корень) - точка сочленения, если у неё есть ребёнок to, для которого low[to] >= tin[v]

Разница с мостом всего в один знак: >= вместо >. Даже если обратное ребро дотягивается ровно до v (не выше) - убрав саму v, всё равно всё оторвётся.

Особый случай: корень

У корня (вершина 0) нет родителя, и условие low[to] >= tin[0] выполняется почти всегда - но это не значит, что корень критичен.

1 ребёнок - не критичен

убрать R - остальное всё ещё связано само по себе

2 ребёнка - критичен!

убрать R - два ребёнка остаются в разных кусках

Корень - точка сочленения, только если у него 2 и больше детей в DFS-дереве

У вершины 0 в нашем графе только один ребёнок (1) - значит, 0 не точка сочленения, хотя формальное условие сработало бы

Проверяем каждую вершину

v → ребёнок low[to] vs tin[v] точка сочленения?
0 → 1 (корень) 0 >= 0 только 1 ребёнок - нет
1 → 2 0 >= 1? нет нет
1 → 3 3 >= 1? да да
3 → 4 3 >= 3? да да
4 → 5 3 >= 4? нет нет
Итог: точки сочленения - {1, 3}. Ровно концы моста, как и ожидалось

Практика

если осталось время

Задача 1: find_bridges

Напиши find_bridges(graph), возвращающую список всех мостов - для нашего графа с занятия.

graph = {0:[1,2], 1:[0,2,3], 2:[0,1], 3:[1,4,5], 4:[3,5], 5:[3,4]}
find_bridges(graph) → [(1, 3)]

Задача 2: find_articulation_points

Напиши find_articulation_points(graph) - переиспользуй код задачи 1, поменяв только условие. Тот же граф:

find_articulation_points(graph) → {1, 3}
58

Что запомнить

  • Мост: ребро (v, to), для которого low[to] > tin[v]
  • Точка сочленения: ребёнок с low[to] >= tin[v] (для корня - особый случай: 2+ детей)
  • Оба ищутся за один проход DFS, O(V + E)
