демо-2027

Алгоритм вычисления значения функции F(n), где n - натуральное число, задан следующими соотношениями:

F(n) = 1 при n = 1;
F(n) = n × F(n - 1), если n > 1.

Чему равно значение выражения (F(3038) + 5 × F(3037)) / F(3036)?

Руками: это факториал, сокращаем. Но мы пишем программу - она не ошибается в арифметике

Условие -> Python

в условиив функции
F(n) = 1 при n = 1if n == 1: return 1
F(n) = n × F(n - 1), если n > 1return n * F(n - 1)
(F(3038) + 5 × F(3037)) / F(3036)выражение - уже вне функции
Каждая строка условия - одна ветка if. База (без вызова F) - первой

Как идут вызовы

слева - наш №16: F(n) зовёт только F(n - 1). Для F(3038) - 3038 вызовов друг в друге

справа - если F(n) зовёт F(n - 1) и F(n - 2): F(3) считается 2 раза, F(2) - 3 раза

Пишем вместе

  • файл 1_demo_f.py: функция F(n) - перевод строка в строку
  • сначала маленькое n: F(5) = 120 - перевод верный
  • делим через //: числа огромные, ответ - целое
  • печатаем сразу выражение, а не F(3038): в нём ~9000 цифр, Python откажется его печатать

запускаем на 3038 и получаем RecursionError

Ловушка 1: глубина

Python разрешает примерно 1000 вызовов друг в друге. Нам надо 3038

import sys

две строки в начале файла, и ответ демо: 9241591

Программа падает молча даже с лимитом (n в сотнях тысяч)? Считаем снизу вверх: F(1), F(2), F(3) ... циклом в словарь

каждый вызов рождает два: для n = 40 это сотни миллионов вызовов

№13 из демо-2027

демо-2027

Исполнитель преобразует число на экране. Команды: A. Прибавь 1, B. Поменяй местами.

Команда B применяется, только если цифра десятков меньше цифры единиц, и меняет местами две младшие цифры.

Сколько существует программ, для которых при исходном числе 100 результатом является число 141?

Траектория - последовательность результатов всех команд. Для программы ABA при числе 13 траектория: 14, 41, 42.

В других вариантах добавляют: «траектория содержит X» и «не содержит Y»

Числа - это вершины

маленький пример: из 2 в 8 командами +1 и x2

программа «x2, x2» - это путь 2 -> 4 -> 8

Сколько программ = сколько путей из 2 в 8. Это занятие 35

Идея: count(a, b)

1
a == b - пришли, это 1 программа
2
a > b - перескочили, числа только растут: 0
3
иначе - сумма count по каждой команде, которую можно применить к a
Все команды увеличивают число - циклов нет, рекурсия всегда закончится

Считаем от конца

count(4) = count(5) + count(8), под числом - сумма по командам +1 и x2

Из 2 в 8 - 5 программ. Рекурсия сделает то же самое, только от 2

Пишем вместе

  • файл 3_demo_programs.py, функция count(a, b)
  • команда A - всегда: count(a + 1, b)
  • команда B - только если десятки меньше единиц: a // 10 % 10 и a % 10
  • новое число: сотни те же, единицы и десятки поменялись местами: 113 -> 131
  • проверка: count(13, 14) = 1, потом ответ

ответ демо: 16

«Содержит 4»

любой путь до 4 склеивается с любым путём после: 2 · 2 = 4

Через X: count(a, x) * count(x, b)

«Не содержит 6»

остались 2 -> 3 -> 4 -> 8 и 2 -> 4 -> 8: 2 программы

Не через Y: первой строкой if a == y: return 0 - число Y стало тупиком

Ловушки

X и Y вместе

произведение двух count, тупик Y - в обоих: Y может стоять и до X, и после

условие команды

«только если» - проверяем до вызова, как B в демо

число уменьшается

«вычти 1» - перевернуть: тупик a < b вместо a > b

Проверь функцию на маленьком числе, которое можно посчитать руками

Вершины могут быть пронумерованы не подряд, L, M ≤ 1000. Числа разделены любым количеством пробелов и табуляций.

Новый номер 2027 года. У Полякова варианты: «через вершину», «не через», «сколько путей»

Одна строка - одно ребро

В файле демо 200 строк - 200 рёбер. Нарисовать нельзя, читаем программой

Читаем файл

graph = {}
for line in open('demo_23.txt'):
    a, b, w = line.split()
    a, b, w = int(a), int(b), float(w)
    if a not in graph:
        graph[a] = []
    graph[a].append((b, w))
  • split() без аргумента режет по любым пробелам и табам
  • словарь, а не список: номера до 1000 и не подряд
  • из вершины-тупика рёбер нет: graph.get(v, [])
